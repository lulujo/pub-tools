## Technical Notes

### WPEngine/Cloudflare 5xx during bulk REST
Hit a transient **522** (and later a **525**) mid-batch. Media uploads are **not idempotent** &mdash; a 522 *after* the image POST succeeded but *before* the alt-text POST left one orphan upload (had to find it via `media?search=` and resume rather than re-upload). The post-create call also took one 525 and succeeded on retry. **Lesson:** wrap all REST calls in a retry-on-5xx loop (now done in the batch scripts), and before re-running a failed upload, search existing media to avoid duplicates.

### Markdown&rarr;Gutenberg converter &mdash; full character coverage
Building on the 2026-06-13 fixes (non-greedy bold for nested italics; smart-quotes-before-em-dash with `*`/`—` in the opening set), this batch added:
- **Ellipsis** `…` &rarr; `&hellip;` (DeAnna)
- **En dash** `–` &rarr; `&ndash;` (Michael, `10–15`)
- **Superscript two** `²` &rarr; `&sup2;` (Michael, `E=mc²`)
- **Bare ampersand** `&` &rarr; `&amp;` via negative-lookahead so existing entities aren't double-encoded (Doug's magazine titles)
- **Accented letters** (e.g. `à`) left as UTF-8 &mdash; correct, WordPress stores UTF-8; only quotes/dashes/ellipsis/`&`/`²` need entities
- **Inline links** `[text](url)` &rarr; `<a target="_blank" rel="noopener">`; links with italic text (`[*Title*](url)`) correctly nest `<em>` inside `<a>`

### Parse fix: multi-word author names in "Find" heading
The Find-section split/`find_name` regex must accept multi-word names (Doug = "Find Douglas Smith"). Use `^##\s+Find\b.*$` to split and `^##\s+Find\s+(.+?)\s*$` to capture. (The single-word `\w+` form from the first batch would have dropped Doug's entire Find section.)
